## 设计与取舍

主实验采用已有真实 UCI LP1 测量，避免把事件标签复制为逐点故障真值。
预先固定前十个 normal 完整事件作参考，其余完整事件作留出测试。
真实事件任务：normal 为负，其余原始类别为正；一个事件任意点/通道触发则预测正。
另建正常留出事件的测量副本，在检测行 150、225、300 六轴替换为 10000。
注入任务的单位为原始样本点，只有人为替换位置为正，其余为非注入背景。
它测量强扰动检出与非注入告警，不代表自然故障逐点识别能力。

比较固定 MAD 阈值 3.5 / 尺度下限 1，与 IF auto / 100 棵树 / max_samples 256 /
种子 42；全部使用相同六轴。参考缩放、模型与阈值只拟合参考区间。
不根据留出标签挑阈值、种子或最佳方法。直接对既定参数报告结果；后续调参需新的验证集。
选择独立事件而非重叠窗口，避免窗口跨划分泄漏；本阶段不增加新的窗口检测器。
指标分母为零时输出 null。所有选定通道均可评分的点才参与；完整可评分事件才参与事件指标，
同时导出覆盖率和排除原因。MAD 行×通道评分先合并为点，不与 IF 点数直接混比。

## 实施步骤

1. `tests/test_evaluation.py` 先验证混淆矩阵、未定义指标、严格标签、逐点归并、
   部分评分和事件排除；运行失败确认后实现 `src/runlens/evaluation.py`。
2. `src/runlens/experiments.py` 实现真实事件/注入点两项实验；输出固定协议、原始/处理后
   SHA、完整事件划分、逐点评分、逐单位预测、种子、版本及真实计时。
   `tests/test_experiments.py` 用真实 fixture 验证无参考扰动、事件隔离、确定性预测和指标回算。
3. `src/runlens/reporting.py` 独立构建当前数据摘要、标准 JSON、Markdown、简单 HTML；
   包含质量规则、已有特征和检测的实际配置/证据/局限。未标注上传数据没有分类指标。
   报告限制表格预览数量，提供总数；完整 CSV 单独导出。所有输入文本进行格式转义。
4. `examples/run_experiments.py` 生成 `examples/generated/phase4/` 中报告、指标、
   预测、划分、评分、配置、原样/扰动 CSV；默认拒绝覆盖，先检查全部输出。
5. `app.py` 增加“实验与报告”：当前数据快照导出，以及明确独立于当前上传文件的
   内置真实记录实验。用提交按钮执行，会话缓存有 TTL/容量，使用原生控件与 alt 文本。
   数据/映射/质量参数和已提交特征/检测变化清除旧报告，避免旧快照冒充当前结果。
6. 更新版本 0.0.5、README、USER_GUIDE、ARCHITECTURE、PRD、TASKS 与
   `examples/PHASE4_RESULT.md`，记录实际运行结果和平台限制；不进入 Phase 5。
